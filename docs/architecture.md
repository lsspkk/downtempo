# Architecture

**Summary**: Data lives in projects (`data/projects/<id>/`, one `Library` each; `Workspace` knows the current one). Providers find a shared folder's media files, `sync` downloads what changed into the project's `downloads/`, the catalog turns those files into its `songs.json`, and the players read only that catalog. The CLI and the player reach all of it through `Workspace` + `Library`. Built: OneDrive provider, sync, sources, library, catalog, projects (core + CLI), settings file (core + CLI), song grouping, the Python player with background downloads and the project screen (sorting by click, key and drag, previews, sources, Add folder from a pasted link, the ☰ main menu, Project settings with Change link); the browser app (MVP, English and Finnish, its own small copy of download and grouping in TypeScript, [browser-app.md](browser-app.md)). Next: the user's try-outs of all of it ([todo.md](todo.md), [purpose.md](purpose.md)).

```
data/projects/<id>/:
project.toml ──provider lists──> sync ──> downloads/<source>/ ──catalog──> songs.json
        CLI, player ──> Workspace (current project) ──> Library (all of the above) ──> songs, events, UserError
```

## Layout

- `src/downtempo/`: shared package, installed by uv; command line `uv run downtempo <command>` (`cli.py`).
  - `config.py`: `DATA_DIR` (`DOWNTEMPO_DATA` overrides it), `TOKENS_DIR`, file endings, wav compression switch and quality, `.env` loading.
  - `library.py`: `Library(root)`: the one API for the CLI and players, one project folder ([blocks.md](blocks.md#apis)).
  - `bundle.py`: the settings file ([settings-file.md](settings-file.md)).
  - `projects.py`: `Workspace(data_dir)` (projects, current, use, create, rename, delete), `migrate` ([projects.md](projects.md)).
  - `sources.py`: `Source(name, type, url, folder, extra_folders)`; `project.toml` read with `tomllib`, written with `tomlkit` (temp + replace).
  - `sync.py`: `plan` (compare a listing with local files) and `run` (download through `.part`, server mtime, cancel between 1 MB chunks), `update` (several sources, one sign-in per provider). `compress.py`: `stored_as` (a server's `Song.wav` is `Song.mp3` on disk) and `to_mp3` (soundfile, cancellable), used by `sync.py`; the requirements for both apps in [compress.md](compress.md).
  - `catalog.py`: builds a library's `songs.json` ([songs.md](songs.md)).
  - `tempo.py`: a recording's tempo estimate (Essentia: pieces, median with half / double folded) and where its beats fall, for the player's click ([tempo-goal.md](tempo-goal.md)).
  - `events.py`: event dataclasses (`SignIn`, `Checking`, `Planned`, `Fetching`, `Saved`, `Skipped`, `Failed`) and `print_report`, the CLI's lines. `errors.py`: `UserError(message, hint)`, `Cancelled`.
  - `downloaders/`: providers, listed in `downloaders/__init__.py` (`PROVIDERS`, `provider_for(url)`). `remote.py` has the `Provider` / `Connection` faces and what they return; `web.py` has `request_error` (a failed request → `UserError`); `onedrive.py` the OneDrive provider.
- `frontends/`: players; they use `downtempo.library` and `projects` (plus `config`, `events`, `errors`), never `downloaders/`. `nicegui/` (Python player, [player.md](player.md)): `app.py` wires the page in a native window (pywebview, Qt on Linux) from one module per part of the screen (`layout.py` frame, `song_list.py`, `controls.py` the controls as one surface + `mini_bar.py` its sheet-only form + `recordings.py` the recording dropdown + one module per tab (`pitch_tab.py`, `trainer_tab.py`, `loop_tab.py`, `bpm_tab.py`), `sheet_pane.py` + `.js`, `loop_editor.py`, `tempo_row.py` + `tempo_goal.py` + `tap_tempo.py` + `metronome.py` the tempo in BPM and the optimal tempo ([tempo-goal.md](tempo-goal.md)), `keys.py`) and `player.py` (what plays, no widgets), `engine.py` Rubber Band stretch + `sounddevice`, `loop_editor.js` the loop editor's canvas drawing and gestures, `sheets.py` PDF pages, `state.py` `data/app.json` + the project's `practice.json`, `jobs.py` background jobs (one at a time, events through a queue drained by a timer), `updates.py` download state for the whole page (⟳, progress, result, errors per folder), `project_panel.py` the song list's top (Project ⟳, name, status line), `sign_in.py` the sign-in card, `welcome.py` the first start, `project_screen.py` + `sort_tab.py` + `songs_tab.py` + `chips.py` + `sources_bar.py` the project screen (sorting by click, the sources; [project-screen.md](project-screen.md)), `add_folder.py` + `folder_picker.py` adding a shared folder from a pasted link, `main_menu.py` + `settings_file.py` the ☰ main menu (settings, switch, new, delete, export / import), `project_settings.py` + `folder_actions.py` + `change_link.py` Project settings (name, folders with their links, sign-in), `waveform.py` the waveform (controls, and large for songs without sheets). `browser/` (the browser app, [browser-app.md](browser-app.md)) can't use the Python core: it has its own OneDrive, download plan and a lite grouping in `src/core/`, with the same rules (sync never deletes, names make songs).
- `data/`: all local material, see [data/README.md](../data/README.md).
- `scripts/`: dev tools: `screenshot.py` (load a page, run JS steps such as key presses, save PNGs: repeatable UI checks of the player in `--browser` mode), `tempo_test.py` (tempo detection on downloaded recordings, [tempo-detection.md](tempo-detection.md)), `stretch_test.py` (the blind listening test's excerpts, [stretch-research.md](stretch-research.md#then-listening-test-t31)).

The planned core's rules ([blocks.md](blocks.md#rules)) join the principles below as they are built.

## Principles

- **Provider code stays in its downloader.** Nothing outside `downloaders/<type>.py` knows about OneDrive or Google Drive. A new provider = one module + one registry line + one doc.
- **A provider only finds files.** `connect(report, cancel)` signs in (a `SignIn` event; cancellable), `open(url, folder)` opens the link at a folder path of any depth, `folders` lists subfolders with counts (the folder picker), `files` lists media files (mp3/wav/pdf, any case) all levels down, `request(file)` gives a fresh URL + headers just before a download. Failures are `UserError`s.
- **Sync writes, never deletes**, except a wav it made into an mp3 ([compress.md](compress.md)). Files go to `<name>.part`, get the server's change time, then are renamed (a wav is encoded to mp3 first; an mp3 made from a wav counts as current by its time alone); a file counts as current when its size matches and its mtime isn't older than the server's. A server name that would leave the source's folder is skipped. Files gone from the server are only counted. A cancel stops between chunks and keeps finished files.
- **The core never prints or asks.** It reports events and raises `UserError`; the CLI prints them (`print_report`), the player shows them. Long calls block and take a `cancel` `threading.Event`; the player runs them through `jobs.py` and touches widgets only from its timer.
- **Frontends never import `downloaders/`.** They call `Library` and know a provider only by its `label`.
- **Frontends read only the catalog** (`songs.json`) and the files it points to, through `library.songs()` and `library.path()`. They never scan folders.
- **Config split**: `.env` = credentials only (it overrides the built-in OneDrive client ID); `project.toml` = the project's name, what to download, and per source how the catalog reads it (`extra_folders`); sign-ins in `data/tokens/`, shared by every library.
- **Private stays local**: real links, folder and song names live only in `data/` (git-ignored). Tracked files use made-up examples.
